# ADR-002: Gaussian calibration -- Balle-Wang, not the classic formula

- Status: Accepted
- Date: 2026

## Context

The Gaussian mechanism needs a noise scale `mu` (where `sigma_abs = mu * sensitivity`)
such that the mechanism is `(epsilon, delta)`-DP. Two calibrations exist:

1. **Classic (Dwork et al. 2014, Thm 3.22):**
   `mu_classic = sqrt(2 ln(1.25/delta)) / epsilon`.
2. **Balle & Wang 2018 analytic calibration:** solve the characteristic equation
   `ndtr(1/(2mu) - eps*mu) - exp(eps)*ndtr(-1/(2mu) - eps*mu) = delta` by
   bisection.

The classic formula derives under the assumption `epsilon in (0, 1)`. For `epsilon >
1` it is no longer a valid upper bound on the required noise. Cross-validation
against `diffprivlib` (`DP_MATH_SPEC.md` appendix A) shows:

| epsilon | delta | mu_BW | mu_classic / mu_BW |
|---|---|---|---|
| 0.1 | 1e-5 | 30.750 | 1.576 (classic looser) |
| 1.0 | 1e-5 | 3.731 | 1.299 |
| 10.0 | 1e-5 | 0.500 | 0.969 (classic **smaller** -> guarantee fails) |

At `epsilon = 10` the classic formula returns a *smaller* `mu` than Balle-Wang,
i.e. it under-noises and the stated privacy guarantee is void -- silently, with no
error.

## Decision

Use `domain/mechanisms.calibrate_gaussian_bw` (Balle-Wang analytic calibration)
everywhere for single-mechanism releases. The classic formula is **forbidden** in
the codebase (INV-12 / I12; source-scan test `test_no_classic_gaussian_formula`).
For multi-step composition (DP-SGD) we instead use the RDP route
(`domain/rdp.calibrate_mu`), which is tighter than Balle-Wang for composed mechanisms.

The Balle-Wang result is locked against `diffprivlib.mechanisms.GaussianAnalytic._scale`
to within 1e-13 (INV-9, `test_mu_bw_matches_diffprivlib`), so `diffprivlib` serves
as the golden reference for the calibration.

## Consequences

Positive:

- Privacy guarantees hold for the full `epsilon` grid the SPEC sweeps (up to 10),
  including the `epsilon > 1` regime where the classic formula fails.
- A single, audit-able calibration function is the one place noise scales are derived
  from a sensitivity.

Negative / trade-offs:

- The classic `gaussian_sigma`/`k_gm` helper in `core/constants.py` is now dead code
  relative to the privacy path; it must not be used for calibration. (Flagged: it
  remains only as an analytic reference and is intentionally not imported by the
  mechanism/accountant layers.)
- Balle-Wang requires a numeric root find (bisection) instead of a closed form, but
  it is cheap and cached.
