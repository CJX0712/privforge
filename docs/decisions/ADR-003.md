# ADR-003: Amplified RDP accountant with ledger decoupling

- Status: Accepted
- Date: 2026

## Context

AdaClip-Budget adapts the per-step clip norm `C_t` to the gradient-norm distribution
(a DP quantile mechanism). A naive DP-SGD would draw noise
`N(0, (mu_t * C_t)^2)` so that the sensitivity is `C_t`. That couples the privacy
ledger to the (data-dependent) clip trajectory and forces a conservative `C_max`
upper bound -- exactly the relaxation that makes prior adaptive-clip methods loose.

Two design decisions are therefore forced:

1. **The RDP accountant must use the Poisson-subsampled Gaussian bound**, not basic or
   advanced composition, otherwise the DP-SGD baseline is a straw man (SPEC pitfall
   #6).
2. **The privacy ledger must not depend on `C_t`.** This is achieved by unit-sensitivity
   normalization (INV-12) so the noise scale is the naked `mu_t`.

## Decision

### Amplified RDP grid

Implement `domain/rdp.rdp_poisson_gaussian(q, mu, alpha)` as a numerical integral in
log space on the grid

```
lo = -max(0, (alpha - 1) * r) - 12
hi =  max(0, alpha * r) + 12         # r = 1 / mu
```

The `+12 / -12` margins are mandatory: the integrand peaks at `z = alpha*r` (and
`z = -(alpha-1)*r` in the reverse direction). A naive `[-10, 10]` grid silently
returns ~half the true value at `alpha=64, mu=2` (4.268 vs 8.0) with no error
(`DP_MATH_SPEC.md` section 2.4, pitfall #11). INV-15 regression-tests the `q -> 1`
degeneration to the closed form `alpha / (2 mu^2)`.

### Ledger decoupling

In `training/dp_sgd.train_dpsgd`, the update is

```
h_i = g_i / max(C_t, ||g_i||)          # ||h_i|| <= 1, independent of C_t
ghat = (sum h_i + N(0, mu_t)) / L      # noise scale = naked mu_t (NEVER mu_t * C_t)
theta -= eta_t * C_t * ghat             # C_t applied in post-processing (free)
acc.step(q, mu_t)
```

Because `||h_i|| <= 1` and the noise std is `mu_t` -- both independent of `C_t` --
the privacy bound `eps_alpha(q, mu_t)` is a function of `(q, mu_t)` alone. The INV-13
test (`test_ledger_independent_of_C_trajectory`) runs the same accountant config under
three distinct `C` trajectories (constant 0.1, constant 100, random jumps) and asserts
the `eps_alpha` arrays are element-wise identical to 1e-12.

`mu * C_t` is forbidden (ablation A6): it is wired only behind the
`unsafe_mu_times_C` flag and exists solely so INV-13 can prove the safeguard test
actually catches the bug.

## Consequences

Positive:

- The budget can be calibrated **exactly before training** (no `C_max` relaxation),
  and `C_t` may adapt arbitrarily each step without changing the privacy guarantee.
- The `mu_t` schedule can be pre-computed in `O(1)` integration calls, since the
  ledger never depends on the realized `C_t`.

Negative / trade-offs:

- The RDP integral must be implemented carefully (log space, correct grid); a subtle
  bug there is silent. Mitigated by INV-15 plus the `diffprivlib` cross-check.
- The `unsafe_mu_times_C` flag must never be reachable from any shipped configuration;
  it is asserted off in normal paths.
